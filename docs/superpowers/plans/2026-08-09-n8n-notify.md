# n8n Workflow & Notify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the app-side "email me this shortlist" flow — an API route that gathers a session's active shortlist and hands it to n8n, a UI button that triggers it, and an importable n8n workflow that turns the shortlist into a PDF and emails it — satisfying the problem statement's "implement an n8n workflow that compiles the shortlist into a PDF and emails it to the user" requirement.

**Architecture:** `POST /api/notify` reads `shortlistItems` (status `active`) joined with `listings` for a session, strips everything down to the non-PII fields the spec allows, and forwards `{ sessionId, shortlist, email }` to the n8n instance's webhook URL (`N8N_WEBHOOK_URL`). n8n (a separate, already-provisioned Railway service — provisioning it is out of scope here) runs a Webhook → Code → HTML-to-PDF → Send Email → Respond-to-Webhook chain and is the only place PDF generation/emailing happens. A small React component (`EmailShortlistButton`) is the UI trigger for the route.

**Tech Stack:** Next.js 15 App Router route handler, Drizzle ORM (`lib/db/schema.ts` / `lib/db/client.ts` from the Scaffold plan), React 19 client component, Vitest + React Testing Library + `@testing-library/user-event`, n8n workflow JSON (Webhook / Code / `n8n-nodes-puppeteer` / Email Send (SMTP) / Respond to Webhook nodes).

## Global Constraints

- No PII (owner/agent names, phone numbers) anywhere in the dataset, UI, or logs — problem_statement.md "Rules". The `listings` table has no such columns by design (see ARCHITECTURE.md §4), and the shortlist payload built in this plan only ever includes `societyName, locality, rent, bedrooms, amenities, sqft`.
- The system must implement an n8n workflow that compiles the shortlist into a PDF and emails it to the user — problem_statement.md, top-level requirement.
- Vitest is used for all Next.js/React unit tests; external calls (`fetch` to the n8n webhook, the DB) are mocked at the module boundary — no real network/API calls in the test suite — ARCHITECTURE.md §1 "Testing" row.
- The n8n workflow JSON itself is not Vitest-testable in the normal sense (it's not executable TS/JS) — this plan uses a structural/shape assertion test (parses the JSON, asserts required node `type`s and connection order) plus explicit manual verification steps instead.
- The n8n instance is deployed as its own Railway service from the official n8n Railway template (ARCHITECTURE.md §3.5, §7) — provisioning/deploying that service is **out of scope** for this plan. This plan only produces the importable workflow JSON and documents how to import it.
- Never embed real SMTP secrets in the workflow JSON — SMTP is referenced by an n8n credential **name** only, configured separately inside the n8n UI.
- `N8N_WEBHOOK_URL` already exists as a key in `.env.local.example` (Scaffold plan) — this plan reads it via `process.env.N8N_WEBHOOK_URL` and does not redefine it.

**Files:**

**Interfaces:**
- Consumes: `db` from `@/lib/db/client`; `shortlistItems`, `listings` from `@/lib/db/schema`; `process.env.N8N_WEBHOOK_URL`.
- Produces: exported `POST(request: Request): Promise<Response>` — a Next.js App Router route handler. Later tasks (`EmailShortlistButton`) call this route over HTTP as `POST /api/notify` with body `{ sessionId: string; email: string }`, and expect a JSON body `{ status: 'sent' }` on success (HTTP 200) or `{ error: string }` on failure (HTTP 400/500/502).

**Behavior decisions (explicit, per task instructions):**
- Empty shortlist (no `active` `shortlistItems` rows for the session): return **HTTP 400** with `{ error: 'No active shortlist items to send for this session' }` and do **not** call the webhook. Rationale: emailing an empty PDF is never useful, and this makes the "nothing to send" case an obvious, testable 400 rather than a silent no-op 200.
- Invalid/missing `sessionId` or `email` in the request body: HTTP 400 with a descriptive `{ error: string }`.
- Webhook unreachable (network error/timeout) or non-2xx response: HTTP 502 with `{ error: string }`. The route must never return `{ status: 'sent' }` unless the webhook call actually returned a 2xx.
- `N8N_WEBHOOK_URL` unset: HTTP 500 with `{ error: 'Notification service is not configured' }` (a misconfiguration, not a client error).

Create `app/api/notify/route.ts`:

```ts
import { NextResponse } from 'next/server';
import { and, eq } from 'drizzle-orm';
import { db } from '@/lib/db/client';
import { shortlistItems, listings } from '@/lib/db/schema';

const WEBHOOK_TIMEOUT_MS = 10_000;
const EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

export async function POST(request: Request) {
  let body: { sessionId?: unknown; email?: unknown };
  try {
    body = await request.json();
  } catch {
    return NextResponse.json({ error: 'Invalid JSON body' }, { status: 400 });
  }

  const { sessionId, email } = body;

  if (typeof sessionId !== 'string' || sessionId.trim() === '') {
    return NextResponse.json({ error: 'sessionId is required' }, { status: 400 });
  }
  if (typeof email !== 'string' || !EMAIL_RE.test(email)) {
    return NextResponse.json({ error: 'A valid email is required' }, { status: 400 });
  }

  const rows = await db
    .select({
      societyName: listings.societyName,
      locality: listings.locality,
      rent: listings.rent,
      bedrooms: listings.bedrooms,
      amenities: listings.amenities,
      sqft: listings.sqft,
    })
    .from(shortlistItems)
    .innerJoin(listings, eq(shortlistItems.listingId, listings.id))
    .where(and(eq(shortlistItems.sessionId, sessionId), eq(shortlistItems.status, 'active')));

  if (rows.length === 0) {
    return NextResponse.json(
      { error: 'No active shortlist items to send for this session' },
      { status: 400 }
    );
  }

  const webhookUrl = process.env.N8N_WEBHOOK_URL;
  if (!webhookUrl) {
    return NextResponse.json(
      { error: 'Notification service is not configured' },
      { status: 500 }
    );
  }

  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), WEBHOOK_TIMEOUT_MS);

  let webhookResponse: Response;
  try {
    webhookResponse = await fetch(webhookUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ sessionId, shortlist: rows, email }),
      signal: controller.signal,
    });
  } catch {
    return NextResponse.json(
      { error: 'Failed to reach the notification workflow' },
      { status: 502 }
    );
  } finally {
    clearTimeout(timeout);
  }

  if (!webhookResponse.ok) {
    return NextResponse.json(
      { error: `Notification workflow rejected the request (status ${webhookResponse.status})` },
      { status: 502 }
    );
  }

  return NextResponse.json({ status: 'sent' });
}
```

```tsx
'use client';

import { useState } from 'react';

type Status = 'idle' | 'loading' | 'success' | 'error';

const EMAIL_RE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

export function EmailShortlistButton({ sessionId }: { sessionId: string }) {
  const [email, setEmail] = useState('');
  const [status, setStatus] = useState<Status>('idle');
  const [errorMessage, setErrorMessage] = useState('');

  const isEmailValid = EMAIL_RE.test(email);

  async function handleClick() {
    if (!isEmailValid) return;
    setStatus('loading');
    setErrorMessage('');

    try {
      const res = await fetch('/api/notify', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ sessionId, email }),
      });
      const data = await res.json().catch(() => ({}));

      if (!res.ok) {
        setStatus('error');
        setErrorMessage(data.error ?? 'Something went wrong. Please try again.');
        return;
      }

      setStatus('success');
    } catch {
      setStatus('error');
      setErrorMessage('Could not reach the server. Please try again.');
    }
  }

  return (
    <div>
      <input
        type="email"
        aria-label="Email address"
        placeholder="you@example.com"
        value={email}
        onChange={(e) => {
          setEmail(e.target.value);
          if (status !== 'idle') setStatus('idle');
        }}
        disabled={status === 'loading'}
      />
      <button onClick={handleClick} disabled={!isEmailValid || status === 'loading'}>
        {status === 'loading' ? 'Sending…' : 'Email me this shortlist'}
      </button>
      {!isEmailValid && email.length > 0 && <p role="alert">Enter a valid email address.</p>}
      {status === 'success' && <p>Shortlist sent! Check your inbox.</p>}
      {status === 'error' && <p role="alert">{errorMessage}</p>}
    </div>
  );
}
```
